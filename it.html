A
reverse.ai

For IT and security teams

Last updated: 10 November 2026 · applies to version 0.1.7 and later; the .pkg installer and managed settings need 0.1.8

At a glance

  • What it is: a small menu-bar (Mac) or tray (Windows) app that notices text typed with the wrong keyboard layout (Hebrew ⇄ English, e.g. akuo instead of שלום) and offers to retype it.
  • Who makes it: Assaf Kazakov, an individual developer in Israel. The Mac app is signed with Apple Developer ID team 29DJ3AH8CK and notarized by Apple.
  • Keystrokes: read to detect the wrong layout, processed in memory on the device, never written to disk and never sent anywhere. Password fields are ignored.
  • Network: one daily version check, plus a report only when the user clicks Report. You can turn off both centrally (section 5). No accounts, analytics, telemetry or third-party SDKs.
  • Permission: macOS Accessibility (it can be pre-approved with a PPPC profile, below).
  • Deployment: a signed, notarized .pkg for Jamf, Intune, Kandji or Munki, or the .dmg.

2. What it does, and why it needs Accessibility

  • Reads key presses through a Quartz event tap (keyboard and mouse-click events) to follow the line being typed. It consumes only the Tab and Esc keys that answer its suggestion bubble, and, right after an automatic fix, the one Backspace that undoes it.
  • Types the correction with synthetic keystrokes: it deletes the mistyped text and types the fix. It never uses the clipboard. Fixes it is sure about are typed automatically (users can turn this off in the menu; it never happens in terminals); the rest wait in the bubble for the user.
  • Reads the text cursor position through the Accessibility API, only to place the bubble next to it. In Electron apps (Slack, WhatsApp, VS Code…) it asks the app to expose that position.
  • Switches the keyboard layout after a fix, if the user wants that.
  • Leaves alone: password fields (macOS Secure Event Input and secure text fields), apps on its exclusion list (password managers by default), and words containing digits.
  • Starts at login as a standard login item (SMAppService); macOS shows the usual "added a login item" notice, and the user can turn it off.
  • Permissions: only Accessibility is required. In rare cases macOS still refuses the keyboard event tap after Accessibility is on; the setup window then also asks the user to allow Input Monitoring. It never needs Screen Recording, Full Disk Access, Automation or any other permission.
  • Other processes: it starts none in normal use. Only when the user clicks Reset and add again in the setup window does it run /usr/bin/tccutil reset Accessibility and tccutil reset ListenEvent, for its own bundle ID only. (Before 0.1.8 it also ran that Accessibility reset by itself at launch while it wasn't approved.) Restart reverse.ai reopens the app through Launch Services, without a shell. The setup buttons open System Settings at the right privacy page, closing it first if it's open so that the list refreshes.

3. Data handling

  • In memory only: the line currently being typed, and the previous line for one minute so the user can report it (not kept when reports are turned off). Never written to disk.
  • On disk: the user's settings (~/Library/Preferences/com.assafkazakov.reverseai.plist) and, only if the user turns it on, a diagnostic log for 24 hours (~/Library/Logs/reverse.ai) with states and counts, never typed text. The log is deleted 7 days after it was last written.
  • Language processing, including the small built-in AI model, runs entirely on the device. Nothing is sent to an AI service.

5. Approving it with device management (macOS)

  • Install: deploy reverse.ai-mac.pkg (section 1) as a package in Jamf, Kandji or Munki, or as a line-of-business macOS app (PKG) in Intune. The .dmg also works with Intune's "macOS app (DMG)" type.
  • Allow the app: by Team ID 29DJ3AH8CK, or by the code requirement above, in your allowlisting tool. In Santa: santactl rule --allow --signingid --identifier 29DJ3AH8CK:com.assafkazakov.reverseai (or --teamid --identifier 29DJ3AH8CK).
  • Pre-approve Accessibility with a Privacy Preferences Policy Control (PPPC) payload, so users need no admin password:
    Service
    Accessibility
    Identifier
    com.assafkazakov.reverseai (type: bundle ID)
    Code requirement
    the string in section 1
    Access
    Allow
  • Input Monitoring, only if a Mac asks for it (section 2): device management can't switch it on, but it can let standard users approve it. Add the same identifier and code requirement under the service ListenEvent, with Authorization AllowStandardUserToSetSystemService.
  • Login item: to approve it ahead of time, add a Managed Login Items payload (com.apple.servicemanagement) with RuleType TeamIdentifier and RuleValue 29DJ3AH8CK. Users then can't turn it off in System Settings.
  • Managed settings (0.1.8 and later): a configuration profile with custom settings for the preference domain com.assafkazakov.reverseai (Jamf: Application & Custom Settings; Intune: Preference file; Kandji: Custom Profile):
    KeyTypeWhen true
    DisableReportsBooleanNo Report button or report menu items, nothing is ever sent, and the previous line isn't kept in memory.
    DisableUpdateCheckBooleanNever contacts update.json, automatically or from the menu. The menu says updates are managed by your organization.
    <key>DisableReports</key><true/>
<key>DisableUpdateCheck</key><true/>
    With both set, reverse.ai makes no network connections at all.
  • Endpoint security tools may flag any app that monitors the keyboard. Some osquery-based checks, for example, report every keyboard event tap from software not made by Apple. This page documents exactly what reverse.ai does, so you can allow it by Team ID, signing ID (29DJ3AH8CK:com.assafkazakov.reverseai) or code requirement.

6. Windows

  • File: a single reverse.ai.exe from the same GitHub releases. The Windows build isn't code-signed yet, so SmartScreen shows "Windows protected your PC" until it's allowed.
  • Runs per user, with no installer, administrator rights, services or drivers.
  • Keyboard and mouse: low-level hooks (WH_KEYBOARD_LL, WH_MOUSE_LL) for the same purpose as on the Mac; it types corrections with synthetic keystrokes.
  • Files: settings in %APPDATA%\reverse.ai\settings.json; working data and the optional log in %LOCALAPPDATA%\reverse.ai.
  • Startup: a reverse.ai value under HKCU\Software\Microsoft\Windows\CurrentVersion\Run, which the user can turn off.
  • Network: the same two requests as on the Mac, and nothing else.

2. מה היא עושה, ולמה היא צריכה נגישות

  • קוראת הקשות דרך Quartz event tap (אירועי מקלדת ולחיצות עכבר) כדי לעקוב אחרי השורה שמקלידים. היא בולעת רק את מקשי Tab ו-Esc שעונים לבועת ההצעה, ומיד אחרי תיקון אוטומטי את ה-Backspace האחד שמבטל אותו.
  • מקלידה את התיקון בהקשות מדומות: מוחקת את הטקסט השגוי ומקלידה את התיקון. היא אף פעם לא משתמשת בלוח ההעתקה. תיקונים שהיא בטוחה בהם מוקלדים אוטומטית (המשתמש יכול לכבות את זה בתפריט, וזה אף פעם לא קורה בטרמינלים); השאר מחכים בבועה למשתמש.
  • קוראת את מיקום הסמן דרך Accessibility API, רק כדי להציג את הבועה לידו. באפליקציות Electron (סלאק, וואטסאפ, VS Code…) היא מבקשת מהאפליקציה לחשוף את המיקום.
  • מחליפה שפת מקלדת אחרי תיקון, אם המשתמש רוצה.
  • לא נוגעת ב: שדות סיסמה (Secure Event Input ושדות טקסט מאובטחים), אפליקציות ברשימת ההחרגה (מנהלי סיסמאות כברירת מחדל), ומילים שיש בהן ספרות.
  • עולה בכניסה למחשב כפריט התחברות רגיל (SMAppService). macOS מציג את ההודעה הרגילה על פריט התחברות שנוסף, והמשתמש יכול לכבות אותו.
  • הרשאות: נדרשת רק הרשאת נגישות. במקרים נדירים macOS עדיין לא מאפשר את ה-event tap של המקלדת גם אחרי שהנגישות הופעלה; אז חלון ההגדרה מבקש מהמשתמש לאשר גם ניטור קלט (Input Monitoring). היא אף פעם לא צריכה הקלטת מסך, גישה מלאה לדיסק, אוטומציה או כל הרשאה אחרת.
  • תהליכים אחרים: בשימוש רגיל היא לא מפעילה אף תהליך. רק כשהמשתמש לוחץ Reset and add again בחלון ההגדרה, היא מריצה /usr/bin/tccutil reset Accessibility ו-tccutil reset ListenEvent, ורק עבור מזהה האפליקציה שלה. (לפני גרסה 0.1.8 היא הריצה את איפוס הנגישות הזה גם לבד בהפעלה, כל עוד לא אושרה.) Restart reverse.ai פותח את האפליקציה מחדש דרך Launch Services, בלי shell. כפתורי ההגדרה פותחים את הגדרות המערכת בעמוד הפרטיות הנכון, וסוגרים אותן קודם אם הן פתוחות, כדי שהרשימה תתעדכן.

3. טיפול במידע

  • רק בזיכרון: השורה שמקלידים כרגע, והשורה הקודמת למשך דקה כדי שאפשר יהיה לדווח עליה (לא נשמרת כשהדיווחים כבויים). אף פעם לא נכתבות לדיסק.
  • בדיסק: הגדרות המשתמש (~/Library/Preferences/com.assafkazakov.reverseai.plist), ורק אם המשתמש מפעיל אותו, יומן אבחון ל-24 שעות (~/Library/Logs/reverse.ai) עם מצבים וספירות, אף פעם לא טקסט שהוקלד. היומן נמחק 7 ימים אחרי הכתיבה האחרונה.
  • עיבוד השפה, כולל מודל הבינה המלאכותית הקטן המובנה, רץ כולו על המכשיר. שום דבר לא נשלח לשירות AI.
  • פרטים: מדיניות הפרטיות.
